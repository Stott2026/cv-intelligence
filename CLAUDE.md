# CV Intelligence

A Stott and May tool. A consultant uploads a PDF or Word CV and gets target companies, live vacancies, selling points, quantified achievements, a pitch guide, an optional job match against a pasted job spec, and an intro email to a hiring manager, and can download the CV formatted as a Stott and May PDF or Word document. Filters: company size (up to 50, 200, 500 or 1,000 employees) and location.

## Stack

- `server.js`: Express. Serves `public/` and `/api/*`. The only place the Anthropic API key is used.
- `lib/extract.js`: PDF (unpdf) and .docx (mammoth) to text, in memory only. Scanned PDFs return a clear 422 message.
- `lib/claude.js`: all Claude calls (`@anthropic-ai/sdk`), cost per call (logged as `claude_call`), web search result URLs.
- `lib/prompts.js`: system prompts and the analysis JSON schema.
- `lib/verify.js`: server-side checks on everything Claude returns (see Rules). Tests in `test/` (`npm test`).
- `public/`: plain HTML, CSS and JavaScript. Model output is only ever inserted with `textContent`.

- `lib/house.js`: signing in through the House (see Sign-in below).
- `lib/anonymise.js`: the Format CV tab's Anonymous option (Basic, Medium, Full pack; agreed with Ian November 2026). One Claude call (`ANON_SYSTEM` in `lib/prompts.js`, about $0.04 to $0.10) removes the candidate's name, contact and personal details and describes every employer, school, university, product, project or award instead of naming it, keeping job titles, dates, skills and figures. Claude lists each replaced organisation with the description it used. The server rejects a result with any number not in the original, or with the candidate's name or any name Claude listed as replaced still in it. The retry tells Claude which names were left (often an employer that is also a skill, such as Salesforce; the prompt says anonymity comes first and to describe it generically there too). If names are still left after the retry, the server swaps in Claude's own descriptions and checks again (`anonymise_scrubbed` in the log); a result with an invented number is always refused. Live fix, 24 November 2026: the first live CV failed twice with 4 names left. The checked text goes back to the browser (`POST /api/anonymise`) and is sent to `/api/format` with `anonymous: true`, which leaves the name out of the pages (agreed with Ian, 26 November 2026): the headline and the Full pack cover show only the job title, the footer shows the job title, and the profile page has no name or nationality boxes; only the file name says "Anonymous candidate". The same Claude call also tidies the layout (one bullet per line, "Job title - employer description, location" with the dates on the next line, sentence-case headings, wrapped lines joined, page furniture dropped). Technology names stay, so a distinctive one (for example a vendor's own platform) can still hint at an employer.
- `lib/wrap.js`: the Format CV tab's "Candidate's own CV" option (agreed with Ian November 2026). The candidate's own PDF, untouched, each page copied with pdf-lib onto a Stott and May frame (`buildOwnFrame` in `lib/format.js`: logo header, white card on `#ECEEF3`, brand footer) after the dark cover sheet. Works with PDF and Word (.docx) CVs and always downloads as a PDF: a Word CV is first turned into a PDF by LibreOffice (`lib/convert.js`, agreed with Ian November 2026), which `railpack.json` installs on Railway with the Calibri, Cambria, Arial and Times look-alike fonts. LibreOffice can only read from disk, so the Word file goes into a private temporary folder that is deleted as soon as the conversion ends (about 4 seconds; a Word file that is not a real .docx is refused). Word CVs built from text boxes, often ones exported from a PDF, can come out with clipped words: the form tells consultants to check the layout. `POST /api/format-own` (multipart: `cv`, `fields`). Because the CV is not changed, the candidate's own contact details stay in: the one agreed exception to the Format CV contact rule below, and the form says so.
- `lib/terms.js`: flags target companies and vacancies we already have Terms with, from Client Radar's private Terms feed (`stott2026/client-radar`, `GET /api/feed/terms-clients`, agreed with Ian November 2026). Server-side only: `TERMS_FEED_KEY` (the same value as in Client Radar's Railway variables) never reaches the browser, the list is cached 10 minutes, and only matches go to the page (a badge with Terms types, account owner, ended or not, and a link to `<CLIENT_RADAR_URL>/?client=<id>`). Matching is deliberately strict to avoid false badges: cleaned-up names (legal suffixes, "The", trailing words like Technology), the employer in an applicant tracking link, or the employer's own website. Current Terms clients are listed first. If Client Radar is unreachable, results come back without badges. Tests in `test/terms.test.js`.
- `lib/format.js`: formats the CV as a Stott and May PDF (pdfkit) or Word file (docx), in memory only. Three templates (structure from Ian's CV Formatter Artifact, look from the Stott and May brand skill's layout patterns): `basic` (CV only), `medium` (Candidate Profile page, then the CV), `long` (dark cover, profile, CV, gradient closing page with the consultant's details, the brand closing line, "Book a hiring 1-2-1" and the About Stott and May boilerplate). Inner pages: teal eyebrow with a hairline rule, Manrope Bold headline with the key phrase in teal, white rounded cards on `#ECEEF3`, outlined chips, and the brand footer (hairline, stack mark, uppercase `#7A8798` text, two-digit page number). The candidate's own email, phone, home address and LinkedIn are always removed from the CV body; a "Contact via Stott and May" block shows the consultant's details in their place. Fonts (Manrope, Inter, SIL Open Font Licence) are in `lib/fonts/`. Page backgrounds (cover, CV page card, closing) and the stack mark are images in `lib/assets/`, shared by the PDF and Word file and drawn by `scripts/make-word-assets.py`; rerun it if the design changes. Section headings always start with a capital letter; a lower-case word that only finishes a wrapped sentence is not taken as a heading; a short line straight before bullets is a label for them. Letter-spaced page furniture (for example from a CV that was already formatted) is removed when a CV is read in (`stripPageFurniture` in `lib/extract.js`) and again before formatting. Tests in `test/format.test.js`.

Routes: `GET /healthz` (no auth, returns `ok`), `POST /api/check`, `POST /api/analyse` (multipart: `cv`, `jobSpec`, `maxSize`, `location`), `POST /api/vacancies`, `POST /api/email`, `POST /api/format` (JSON: `template`, `format` pdf or docx, `cvText`, `fields`, optional `anonymous`; returns the file), `POST /api/anonymise` (JSON: `cvText`, `name`, `summary`, `achievements`), `POST /api/format-own` (multipart: `cv` PDF or .docx, `fields`). Every `/api` route needs a signed-in person (see Sign-in). `GET /session` (no auth) tells the page whether you're signed in and where to sign in; `POST /signout` signs you out of this tool. `GET /house-link` (no auth) returns the House's hallway address for the "The House" button in the top bar (November 2026).

## Sign-in (through the House, November 2026)

Agreed with Ian: people sign in once, at the House (`stott2026/the-house`, an emailed 6-digit code), and this tool trusts it. Going through the Gallery's door arrives with `?house_pass=…`: a pass signed by the House (Ed25519), naming the person and this tool's address, valid 60 seconds and once only. `lib/house.js` checks it with the House's public key (fetched from `<HOUSE_URL>/auth/pass-key`, refetched if the House's key changes), sets this tool's own signed cookie (`cvi_session`, 7 days) and tidies the address. Opening the tool without being signed in redirects to `<HOUSE_URL>/pass?for=<this address>`, which signs you in to the House if needed and sends you back with a pass. "Sign out" signs out of this tool and goes back to the House's hallway. Backup, switched off: `BACKUP_ACCESS_CODE=true` on Railway makes the old shared `ACCESS_CODE` work again (only for if the House is down). Don't change sign-in from another chat without checking with Ian: it's shared with the House and the other tools.

Settings: `ANTHROPIC_API_KEY`, `HOUSE_URL` (needed for sign-in), optional `SESSION_SECRET` (signs this tool's cookie; without it one is made at start-up and people are sent through the House again after a restart), `ACCESS_CODE` with `BACKUP_ACCESS_CODE=true` (the backup only), optional `CLIENT_RADAR_URL` and `TERMS_FEED_KEY` (the Terms badges; both needed), optional `ANTHROPIC_MODEL` (default `claude-opus-5-5`), `PORT`, and `HOUSE_URL` also shows a "The House" button in the top bar, to `<HOUSE_URL>/?hallway` (this tool is the Gallery there). Locally they go in `.env` (git-ignored, never commit it); on Railway they are service variables only. `.env.example` lists every name.

## Rules (do not break these)

- **Secrets**: the API key, the access code and the session secret never reach the browser or the repo.
- **No invented figures, companies or links anywhere.** Enforced in `lib/verify.js`, not just in prompts:
  - A number may only be shown if it appears in the CV text. Achievements tagged "From CV" must have a figure found in the CV; otherwise they become "Inferred - check" with no figure, or are dropped. Emails quoting a number not in the CV are regenerated once, then refused.
  - Companies above the chosen size limit, or without a size estimate, are removed. The limit can never exceed 1,000.
  - A vacancy is only shown if its URL appeared in the web search results of that same call.
- The Job match tab only appears when a job spec is pasted.
- Format CV: the profile page is pre-filled only from checked analysis output (summary, achievements marked "From CV"); salary, notice and so on are typed by the consultant. Never put the candidate's own contact details in a formatted CV (except "Candidate's own CV", which is deliberately untouched and warns about it).
- CVs are not stored. Do not add a database or logging of CV content.

## Brand

Stott and May brand, checked against the stott-and-may-brand skill in November 2026 with the same values as the House (`stott2026/the-house`, `web/src/styles/tokens.css`). All colours are tokens at the top of `public/styles.css`, with a light and a dark set.

- Type: Manrope for headings and page text; Inter only inside cards, data and small labels. Eyebrows are Manrope Light (300), uppercase, letter-spacing 0.12em.
- Gradient teal `#00C8C8` to aquamarine `#73F7BB`. Neutrals `#111314`, `#7A8798`, `#C3CAD2`, `#ECEEF3`, `#FFFFFF`.
- Light: page `#ECEEF3`, white cards (20px corners, no border) with the soft shadow `0 6px 24px rgba(17,19,20,.08)`. Small teal text and focus rings use the darker `#007A7A`, never brand teal (it fails contrast on white).
- Dark: page `#111314`, cards fade from `#1B1E20` to `#050606`, muted text `#7A8798` on the page and cards, a lighter grey (`#A3AEBC`, `--muted-in`) on the grey tiles inside a card where `#7A8798` would fail contrast. The chosen Format CV template gets the brand's aquamarine glow.
- Headline accent on a phrase only; dark text on gradients, never accent colour.
- Official transparent logo files in `public/` (`logo-light-bg.png`, `logo-dark-bg.png`, identical to the brand skill's), no white box behind the logo. Light and dark mode, works at phone width.
- British English, "Stott and May" written in full, spaced hyphens ( - ) instead of em dashes (also enforced by `houseStyle()` on model output).
